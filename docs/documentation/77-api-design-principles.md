# 77. API Design Principles

APIs are product surfaces.

Design them intentionally.

---

---

# Core Principles

APIs should be:

```txt
predictable
composable
minimal
powerful
```

---

# Naming Rules

Prefer:

```txt
clear verbs
clear nouns
consistent vocabulary
```

Avoid ambiguity.

---

# Consistency

Patterns should repeat.

Users should predict APIs.

---

# Ergonomics

APIs should feel natural.

Low friction.

High clarity.

---

# Design Rules

Prefer:

```txt
explicit over magic
sensible defaults
strong typing
```

---

# API Shapes

Examples:

```txt
fluent
functional
object oriented
```

Use intentionally.

---

# Stability

Public APIs need:

```txt
compat promises
deprecation strategy
```

---

# Error Design

Errors should be:

```txt
typed
actionable
documented
```

---

# Documentation Coupling

Every public API documented.

No exceptions.

---

# Anti Patterns

Avoid:

```txt
surprising side effects
unstable signatures
inconsistent naming
```

---

# FAQ

Small APIs need principles docs?

Yes.

Can ergonomics beat minimalism?

Balance both.
